# crate-plugins

Installable plugins for [crate](https://github.com/MattLarritt/cratemusic), the self-hosted
music library, player and recommender.

crate's admin page connects to this repository, reads its catalog, and installs a plugin into
`/data/plugins/<id>/` — no rebuild of crate, no new container. Switch one off and its UI
disappears; switch it back on and it returns.

## The plugins

| Plugin | What it does |
|---|---|
| [**Chords & notes**](docs/plugins/chords.md) | Chord sheets and tabs for your songs, on the player. Paste an Ultimate Guitar link or type your own; read it in columns like sheet music, with guitar or ukulele diagrams and a transpose control. |
| [**YouTube**](docs/plugins/youtube.md) | When a song isn't in your library, find it on YouTube and play it straight away — in the web search, and through OpenSubsonic, so a phone app or a voice request just plays it. Keep the ones you want and they're downloaded into your library. |

## Quick start

In crate, open **Admin → Plugins**, set the repository to `MattLarritt/crate-plugins`, and
press **Install** on a plugin. A plugin with a server half needs one restart, which the same
page offers. Full details in [Installing plugins](docs/installing.md).

## Why everything here is pre-built

crate's runtime image has no compiler, and its web client is a single prebuilt bundle. So a
plugin ships as built files: `npm run build` writes each plugin's `dist/` and regenerates the
catalog (`index.json`), and `dist/` is **committed** — what is in git is exactly what crate
installs. See [Writing a plugin](docs/writing-a-plugin.md#building-and-publishing).

## Repository layout

```
index.json                 the catalog crate reads — generated by npm run build
build.mjs                  builds every plugin into its dist/
plugins/<id>/
  manifest.json            id, name, version, description, which files exist
  server/index.ts          the server half (optional)
  client/index.tsx         the client half (optional)
  dist/                    what crate installs — committed
types/contract.ts          the plugin contract, mirrored from crate
types/crate-modules.d.ts   the crate/* modules a client half may import
shims/                     how those modules resolve to crate's own copies at runtime
docs/                      this documentation
```
